# PhiloVista-1800 标注员操作指南（试标草案 v0.1）

本指南用于 100 张试标。只有 G1 校准通过后才升级并冻结为 v1.0。标注者只依据图片作答，不搜索图片、不查看文件来源，也不猜测上游数据集原答案。

**输出语言：所有自由文本字段必须使用英文。** 这包括 `target_subject`、四轴参考、可见锚点、象征映射、哲学解释、替代解释、限制和仲裁理由。固定 ID、枚举值及兼容 CSV 的中文列名保持不变。若图中含非英文文字，可用英文概述其可见含义；无法可靠读取时写明文字不可辨认，不进行猜测。

## 1. 每张图的操作顺序

1. 先完整看图，辨认真实画面、图中图、广告、屏幕、镜像和文字。
2. 写 `target_subject`，明确本次四轴围绕谁或什么描述。
3. 先写可见事实：一条 `Object`。
4. 再分别回答 Scene、Action、Rationale。
5. 写哲学扩展时，必须先列可见锚点，再选概念和给出解释。
6. 最后记录证据不足、文字依赖、文化背景依赖和歧义。

提交前检查：四轴不能互相复制，不能出现全角分号 `；`，不能填写“无”“同上”“看图”等占位词。

## 2. 四轴问题

### Scene：画面处于什么场景？

写图中可支持的地点或情境，通常是短语或短句。

- 合格：“城市道路旁”“室内工作台前”“象征性的沙漠场景”。
- 太具体：“北京某大学实验室”——除非画面文字和建筑证据足够明确。
- 错轴：“一个人在奔跑”——这是 Action。

### Action：主体正在做什么？

优先写可见动作；没有动作就写可见状态。区分真实主体与广告、屏幕、雕塑、照片中的被描绘主体。

- 合格：“两人正看着同一部手机”“一只熊正在穿过道路”“画面中的秤两端保持不平衡”。
- 证据不足：“他正在赶去参加重要会议”——“赶去”和会议目的通常不可见。
- 图中图：“卡车广告上画着骑车人”不能写成“街上的人正在骑车”。

### Rationale：为什么做这件事，或为什么出现这一情境？

这是合理解释，不是历史事实。先判断证据等级：

- `visual_support`：目的有直接可见线索，如球拍、球场与击球动作支持“为了进行网球比赛”。
- `commonsense_inference`：合理但仍是常识推测，如持伞可能是为了挡雨。
- `insufficient_evidence`：画面无法区分目的，写“仅凭图像无法确定其目的/原因”。
- `not_applicable`：确实没有可适用的行动或目的对象。

不要确定地补写姓名、职业、亲属关系、国家、过去经历、未来计划或内心想法。行李搬运画面通常不能仅凭一帧确定是装载还是卸载；允许三位标注者形成不同但合理的答案。

### Object：具体视觉描述

写一条完整句子，覆盖主要对象、动作/状态、关系和必要的环境信息。它不是类别列表，也不是对图意的哲学解释。

- 合格：“一名男子坐在长椅上看书，耳边戴着耳机，背景有树木。”
- 不合格：“男子，长椅，书，树。”
- 不合格：“这表现了知识使人自由。”——这是哲学解释。

Object 的五条描述允许关注点和粒度不同，但每条都必须单独成立。

## 3. 哲学扩展

### 3.1 可见锚点

`visual_anchors_json` 至少 1 项，每项写可在图中指出的对象、位置、关系、姿态、构图或文字。例如：

```json
["画面中央的人站在岔路口", "两条道路朝不同方向延伸"]
```

不能把“自由”“命运”“人生选择”当作可见锚点；它们是概念或解释。

### 3.2 象征映射

只有画面存在跨域映射时填写，格式为自然语言关系，例如：

```json
["岔路映射为互斥的人生选择", "远方道路映射为选择后的未知后果"]
```

普通纪实场景没有明确象征中介时填 `[]`，不要强行制造隐喻。

### 3.3 概念与解释

正式概念使用 `ontology/philosophical_image_label_system_formal_632.csv` 中的 `PHC-xxx` ID。旧草稿中的 11 个粗粒度值只写入 `legacy_axis_ids`，不得写入正式 `concept_id`。`legacy_axis_crosswalk.json` 只用于检索候选；标注者必须根据当前图片逐项确认，也可不选任何正式概念。

每个正式概念写成独立的 `concept_claims` 项，并明确：`concept_id`、有限强度的 `claim`、支持它的 `visual_anchor_indices`、需要时的 `symbolic_mapping_indices`、该概念主张自身的 `sufficiency` 与 `limitations`。不得用一段共享解释替代逐概念证据核验。

合格解释应形成“锚点 → 映射/关系 → 有限结论”的链条，并说明不能推出什么。例如：

> 人站在岔路口且道路分向两侧，这一构图可被理解为必须在互斥可能性之间作出选择；但图像不能确定人物实际面临的具体决定。

只写“这体现存在主义”“人生如路”“很有哲理”均不合格。

### 3.4 证据充分性

- `supported`：解释有明确、具体且多处一致的可见支持。
- `plausible`：有锚点，但仍依赖常见象征或背景假设。
- `insufficient`：可见内容不足以支持正向哲学命题；边界样本应说明不足在哪里。
- `not_applicable`：当前扩展确实不适用，不等于偷懒或“看不懂”。

每张图可保留 0–3 条合格解释。三条是旧 AI 草稿的候选槽位数量，不是正式标注必须凑满的答案数。

### 3.5 文字与文化依赖

`text_dependency`：

- `none`：无有意义文字，或文字与理解无关；
- `low`：文字提供细节，但不读仍可理解主要画面；
- `medium`：文字明显缩小解释范围；
- `high`：不读文字就无法理解核心冲突、角色动机或隐喻。

`cultural_context_required=true` 只在解释依赖特定符号、宗教、习俗、典故或历史背景时使用，并在 limitations 说明依赖内容。不要把一般生活常识都标为文化依赖。

## 4. 常见失败模式

| 失败 | 识别方式 | 正确处置 |
|---|---|---|
| 把上游短语当答案 | 文本与图像不贴合，却像完整成语/隐喻 | 只按图重写；无法支持则 insufficient |
| 把图中图当真实事件 | 广告、屏幕、壁画中的人物被写成现场人物 | 明确“广告上/屏幕中/画面中的描绘” |
| Object 写成标签 | 只有名词列表 | 改为完整关系句 |
| Action 与 Rationale 混淆 | 两栏都写“在工作/参加比赛” | Action 写正在发生；Rationale 写可能目的 |
| 具体身份臆测 | 无证据写教师、警察、母子、某国人 | 使用“人物/成人/孩子”等可见层级 |
| 强行哲学化 | 无锚点，只套用哲学名词 | 降为 plausible/insufficient，或留空 concept |
| 用不确定词逃避观察 | 所有栏都写“可能、也许、无法判断” | 可见事实照常写；只对不可见原因降置信 |
| 为多样性同义改写 | 一人写三条或照着别人改写 | 每人只写自己的独立一条 |

## 5. 提交规范

- JSON 数组字段必须是合法 JSON，如 `[]`、`["锚点一", "锚点二"]`。
- 时间使用带时区 ISO 8601，例如 `2026-09-06T14:30:00+08:00`。
- `annotation_id`、`annotator_id` 由系统分配，不能自行复用。
- 原始提交不可覆盖。退修使用新 revision，并引用原 annotation_id。
- 发现图片损坏、错图、敏感内容或界面泄露来源时停止该图，提交管理员问题单，不自行搜索补图。
